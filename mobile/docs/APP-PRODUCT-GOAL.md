## 目標調整（已確認）

| 舊目標 | 新目標 |
|---|---|
| 以學習為主，UI 先能用即可 | **把網頁版做成原生 App**（功能 + 視覺對齊） |
| 一次學很多基礎設施 | **一頁做完再下一頁** |
| Push 當主線 | Push 已打通，之後當基礎設施穿插 |

**推進順序：**

1. **活動（Events）** — 做法 B（手機互動 + 視覺對齊）  
2. **首頁（Home）** — 品牌大標 + 主視覺接近網站手機版  
3. 專訪 → 收藏 → 登入（之後再排）

**共存原則：**

- App 繼續打 `https://cyc-zine.vercel.app/api/*`（或本機測）
- **日常改版只動 `mobile/`**
- 活動頁縣市篩選在 **App 端**用現有 `/api/org` 做，**本階段不開新 API**
- 若之後真的需要新 Next.js API／改既有 API：
  - 才會動到線上 web 專案（deploy）
  - **動手改之前必須先取得你的同意**
  - 以「新增 API、不破壞舊網站」為優先
- 此 repo 的 `/frontend` 已 ignore；活動頁改版**只碰 `mobile/`**

## 活動頁做法 B（本階段規格）

### 互動（手機版，不是 1:1 搬 SVG）

```
進入活動
  → 點「選擇縣市」（可搜尋的列表／含「全部」）
  → 選一個縣市
  → 只顯示該縣市活動列表
  → 點卡片 → 既有詳情頁
```

- 不實作完整台灣 SVG 地圖（成本高，之後可選做）
- 不用橫滑 chips（縣市太多滑不完）
- 「全部」選項：可看全部活動（方便除錯／少數跨縣市需求）

### 視覺（對齊品牌，不是複製 DOM）

- 從網站抽 **顏色／字級／卡片比例／間距** 做成 App theme（`StyleSheet` 或簡單 tokens）
- 卡片：圖、活動名、日期、地點；風格接近網站 Event／Carousel 資訊層級
- 詳情頁一併調到同一套 tokens（同一階段內做完才算「活動頁完成」）

### 明確不做（本階段）

- 改線上網站任何檔案
- 為活動頁新增／改 production API
- 登入、收藏、專訪內容
- 完整 SVG 地圖

### 完成定義（DoD）

- [x] 可選縣市（含「全部」）
- [x] 列表只顯示該縣市（或全部）
- [x] loading / error / empty 清楚
- [x] 卡片與詳情視覺明顯比現在接近 CYC ZINE
- [x] 點卡片進詳情、可返回
- [x] **網站行為與畫面無任何改動**
